# AulaGen

**Turn teaching materials into reviewable, student-ready virtual classrooms with AI.**

AulaGen helps educators upload their course materials, organize them into a navigable curriculum, generate supporting learning content, and publish only the material they approve. Its retrieval-augmented assistant answers student questions from the teacher's own sources and returns citations.

## Why AulaGen

Creating a well-structured online classroom from existing notes, slide decks, and readings takes time. AulaGen keeps the educator in control:

1. **Upload and index source material** — PDF, DOCX, PPTX, XLSX, TXT, links, and video references are processed into searchable content chunks.
2. **Generate a proposed course structure** — AI suggests modules, lessons, activities, a glossary, and supporting content from the uploaded materials.
3. **Review before publishing** — educators can edit, approve, reject, reorder, or regenerate AI output before students can see it.
4. **Deliver a student experience** — published courses include lesson navigation, learning progress, self-check activities, bibliography, semantic search, and a source-grounded AI assistant.

## Key capabilities

| Area | Included capabilities |
| --- | --- |
| Educator workspace | Course creation, material management, drag-and-drop curriculum organization, lesson editing, and publication controls |
| AI-assisted authoring | Curriculum proposals, lesson content, activities, questions, and glossary generation |
| Grounded student assistant | Retrieval-augmented answers constrained to course materials, with source references |
| Student classroom | Public course pages, module and lesson navigation, progress tracking, search, activities, bibliography, and complementary resources |
| Governance | Role-based educator and administrator areas, generation history, rate limiting, and explicit review before AI-generated content is published |
| AI flexibility | Ollama, Google Gemini, OpenAI, OpenAI-compatible custom endpoints, or a local heuristic fallback |

## Quick start

### Docker (recommended)

**Requirements:** Docker Desktop and Docker Compose v2.

```bash
git clone https://github.com/alyohara/aulagen.git
cd aulagen

cp .env.example .env
docker compose up -d --build

# Generate an application key if it was not generated by the entrypoint.
docker compose exec app php artisan key:generate
```

Open <http://localhost:8000>. The Compose stack starts the Laravel application, Horizon worker, PostgreSQL with pgvector, and Redis. To include a local Ollama service, run:

```bash
docker compose --profile ollama up -d
```

### Local development

**Requirements:** PHP 8.2+, Composer, Node.js 22+, and the PHP extensions required by Laravel. SQLite is used by default.

```bash
git clone https://github.com/alyohara/aulagen.git
cd aulagen

composer install
npm install
cp .env.example .env
php artisan key:generate

# PowerShell
New-Item -ItemType File -Force database\database.sqlite

php artisan migrate --seed
npm run build
php artisan serve --host=127.0.0.1 --port=8000
```

In a separate terminal, start the queue worker when using asynchronous jobs:

```bash
php artisan horizon
```

The Composer development command can also run the application server, queue listener, logs, and Vite development server together:

```bash
composer run dev
```

## AI configuration

AulaGen uses `config/ai.php` and environment variables to select an AI provider. The default `auto` mode attempts the configured primary provider and falls back to the local heuristic provider when it is unavailable.

```dotenv
AI_PROVIDER=auto
AI_AUTO_PRIMARY=ollama
AI_FALLBACK=local
AI_ENABLED=true

OLLAMA_HOST=http://127.0.0.1:11434
OLLAMA_MODEL=llama3.2
OLLAMA_EMBED_MODEL=nomic-embed-text

GEMINI_API_KEY=
OPENAI_API_KEY=

AI_EMBEDDING_DIM=768
AI_RAG_TOP_K=6
AI_RATE_LIMIT=10
AI_MAX_UPLOAD_MB=40
```

Available provider values are `auto`, `ollama`, `gemini`, `openai`, `custom`, and `local`. Keep API keys out of version control; `.env` is intentionally ignored.

## Deployment notes

Docker Compose is a development-friendly stack. Before production use, configure a production `APP_KEY`, disable debug mode, provide secure database and Redis credentials, persist storage, use an HTTPS-capable web server or reverse proxy, and select an AI provider appropriate for your data-handling requirements.

The GitHub Pages site is a static project presentation only. It cannot run the Laravel application; deploy AulaGen itself to infrastructure that supports PHP, a database, Redis, background workers, and persistent storage.
